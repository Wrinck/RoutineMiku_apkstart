**Лаунчер Android-приложений для Windows — запуск и установка приложений Android так же просто, как нативных программ Windows.**
*Примечание: проект находится на ранней стадии разработки, создан автором в качестве пет-проекта. Все доработки делаются в свободное время после работы и по выходным. Проект бесплатный, с открытым исходным кодом, без рекламы и коммерческого продвижения.*

- 🖱️ **Установка по двойному клику на .apk**: после регистрации файловой ассоциации двойной клик по APK-файлу в Проводнике автоматически парсит пакет → устанавливает → создаёт ярлык на рабочем столе. Интерфейс эмулятора открывать не требуется.
- 🧩 **Отдельный ярлык для каждого приложения**: иконка извлекается прямо из APK в офлайн-режиме и конвертируется в многослойный ICO. Двойной клик по ярлыку = прямой запуск нужного приложения с опытом использования нативной программы Windows.
- 🪟 **Приложение как отдельное окно**: среда запускается в оконном режиме (в headless-режиме Android не генерирует VSYNC — процесс жив, но экран пустой). ApkStart меняет заголовок окна, устанавливает реальную иконку приложения, выставляет портретные пропорции и центрирует его. В **полноэкранном режиме** окно занимает всю высоту экрана по центру; в **оконном режиме** его можно свободно перемещать и масштабировать (размеры запоминаются отдельно для каждого приложения).
- 🔍 **Поиск через Windows**: при установке создаются ярлыки на рабочем столе и в меню «Пуск» (`Программы\ApkStart\`). Приложения находятся обычным системным поиском Windows по названию, а на панели задач группируются отдельно.
- 📁 **Обмен файлами**: папка `%USERPROFILE%\ApkStartShared` непрерывно и в обе стороны синхронизируется с `/sdcard/ApkStartShared` внутри Android. Файлы, сохранённые приложением, мгновенно появляются на вашем ПК.
- 🪶 **Максимальная легковесность**: оболочка не содержит сторонних зависимостей (парсеры ZIP / PNG / ICO / AXML написаны с нуля). Среда выполнения поднимается по требованию и автоматически выгружается при простое. Также можно использовать уже установленные в системе компоненты Android без лишнего расхода памяти.

## Скачать и запустить (без самостоятельной сборки)

Оба источника содержат идентичные файлы:

- GitHub: [github.com/RoutineMiku/apkstart/releases](https://github.com/RoutineMiku/apkstart/releases)
- Gitee: [gitee.com/daily-miku/apkstart/releases](https://gitee.com/daily-miku/apkstart/releases) (альтернативное зеркало)

Варианты сборки (версии и содержимое функционально идентичны):

| Вариант | Имя файла | Когда выбирать |
|---|---|---|
| Версия для Microsoft Store | `ApkStart_<версия>_x64.msix` | Установка из Microsoft Store. Содержит полную среду выполнения, работает без интернета после установки; обновления через магазин |
| Полная портативная (Full Portable) | `ApkStart-v*-win64-full.zip` (~830 МБ, распакованный ~1.3 ГБ) | **Без установки и без ожидания загрузки**: распаковал и запустил, среда выполнения (эмулятор + системный образ) уже внутри архива |
| Инсталлятор (Setup) | `ApkStart-v*-Setup.exe` (~1.3 ГБ) | Классический установщик: ярлыки на рабочем столе/в меню «Пуск», деинсталлятор в системе |
| Легковесная портативная (Light Portable) | `ApkStart-v*-win64-portable.zip` (96 МБ, распакованный ~227 МБ) | Быстро попробовать: среда выполнения загружается из сети при первом запуске |

> В `ApkStart.exe` во всех вариантах прописаны **фирменная иконка и метаданные версии** (FileDescription = `ApkStart 安卓应用运行器`, CompanyName = `RoutineMiku`, версия синхронизирована с `package.json`), а не стандартная иконка Electron с версией `33.x`.
> Команды самостоятельной сборки: `npm run pack` (легковесная) / `npm run pack:full` (полная) / `npm run build:msix` (пакет MSIX).

### Как устроено отображение и заполнение экрана

Физическая ориентация дисплея эмулятора (`hw.lcd.width/height`) определяет реальную форму экрана. Если ориентация дисплея не совпадает с объявленным в приложении параметром `screenOrientation`, Android отображает приложение в виде узкой полосы по центру («letterbox») с чёрными полями по бокам — и это невозможно исправить ни изменением размера окна, ни `wm size`, ни стилями letterbox (все эти варианты были протестированы, подробности в комментариях к `src/core/apk.js`).

Поэтому ApkStart **во время установки APK в офлайн-режиме парсит `AndroidManifest.xml`**, определяя, является ли приложение горизонтальным или вертикальным (с учётом приоритета стартовой Activity; для приложений с `sensor` / `fullSensor` фактическое значение запрашивается у Android при первом запуске). Результат сохраняется в `apps.json`, и при запуске выбирается подходящий дисплей:

- Вертикальные приложения → вертикальный дисплей 720×1280, ориентация нормальная, заполнение по высоте, density 190 (sw606dp) с поддержкой планшетного интерфейса;
- Горизонтальные приложения → горизонтальный дисплей 1280×720, нормальная ориентация, полное заполнение.

Перезапуск среды требуется только один раз — при несовпадении текущей ориентации дисплея и запускаемого приложения (~40 секунд, с уведомлением в заголовке окна). Последующие приложения с аналогичной ориентацией стартуют мгновенно. Кнопка поворота в заголовке **запоминает** ориентацию для конкретного приложения (не затрагивая остальные), а в меню «Настройки → Окно приложения → Ориентация экрана» можно принудительно выбрать «Только альбомная» или «Только портретная».

Вёрстка интерфейса зависит от логической плотности (dp): ширина 720 при 190 dpi даёт ровно **606dp**, что превышает планшетный порог Android в 600dp. Это включает двухколоночный планшетный режим (в стандартном образе при 320 dpi получается всего 360dp — смартфонный режим). За это отвечает переключатель «Планшетная вёрстка» в настройках (включён по умолчанию).

### Онлайн-обновления (автовыбор быстрого зеркала)

«Настройки → **Обновление ПО** → Проверить обновления» либо правый клик по иконке в трее → «Проверить обновления». При обнаружении новой версии нажмите «Обновить сейчас».

- Для установочной версии загружается `ApkStart-v*-Setup.exe` и выполняется тихая установка;
- Для портативной версии загружается `ApkStart-v*-win64-portable.zip` и перезаписывает **каталог программы**. Каталог среды выполнения (`%APPDATA%\apkstart\runtime`), установленные приложения и снапшоты хранятся отдельно, поэтому обновление ничего не затирает;
- Замена файлов выполняется изолированным скриптом PowerShell (ожидание завершения основного процесса → перезапись файлов → повторный запуск) — **без всплывающих окон с просьбой закрыть программу вручную** и без зависших окон эмулятора на рабочем столе.

Процесс обновления не привязан жестко к одному серверу, а **динамически тестирует доступные источники**:

1. Одновременно опрашиваются GitHub и Gitee, выбирается более свежий релиз (недоступность одного источника не блокирует другой);
2. Формируется список кандидатов (прямой адрес, зеркало Gitee, CDN-прокси), с каждого скачивается пробный фрагмент 256 КБ; скорость замеряется только после получения первого байта (время рукопожатия исключается);
3. Загрузка производится параллельными потоками с самого быстрого сервера; при сбое происходит автоматическое переключение на следующий.

В настройках в разделе «Источники загрузки и обновлений» можно зафиксировать нужный источник (актуально для корпоративных сетей с белыми списками доменов), отключить публичные зеркала или указать собственный прокси-префикс.

Оба репозитория публичные, список релизов доступен анонимно без токенов (токен требуется указывать в настройках только при превышении лимитов API 403/429).

**Поведение по умолчанию из коробки**:

- Автозапуск при старте Windows, работа в системном трее; двойной клик по ярлыку на рабочем столе сразу запускает приложение.
- При установке APK автоматически создаются ярлыки **на рабочем столе и в меню «Пуск»**, приложения доступны через системный поиск Windows; отсутствующие ярлыки старых версий восстанавливаются при запуске.
- Нативный рендеринг окна (не видеостриминг): в **полноэкранном режиме** масштабирование по высоте экрана с сохранением мобильных пропорций; в **оконном режиме** сохранение портретных пропорций, свободное изменение размера (разрешение запоминается для каждого приложения). Переключение по клавише `F11` или через контекстное меню трея.
- Автоматическая выдача всех запрашиваемых разрешений при установке (без блокирующих системных диалогов); при аварийном завершении приложения выполняется повторный запуск (при необходимости — с предварительным сбросом данных).
- **Прямое использование сети хоста**: сеть работает через пользовательский NAT QEMU, трафик идёт напрямую через сетевую карту компьютера. **Никаких виртуальных сетевых адаптеров или виртуальных коммутаторов в Windows не создаётся** (драйверы не требуются). Дополнительные настройки сети не нужны.

## Сборка из исходного кода

```powershell
# 1. Установка зависимостей (включая рантайм Electron)
npm install

# 2. Запуск и первоначальное развертывание среды (однократная загрузка adb / Android Emulator / системного образа)
npm start

# 3. (Опционально) Регистрация ассоциации файлов .apk (установка по двойному клику)
npm run assoc:on

# 4. Сборка портативной версии (не требует установки, готова к распространению)
npm run pack
# Результат: dist/ApkStart-win64-portable/ApkStart.exe

# 5. Сжатие в ZIP для релиза (рекомендуется этот скрипт, а не Compress-Archive, чтобы размер был минимальным)
node build/zip.js dist/ApkStart-win64-portable ApkStart-win64-portable.zip
```

### Сборка единого EXE (со встроенной полной средой, без докачки из сети)

Если требуется собрать автономный установщик формата «один файл запустил — всё сразу работает»:

```powershell
# 1. Подготовка каталога engine/ к дистрибуции (системный образ system.img сжимается xz/LZMA2 с 3.1 ГБ до ~1.1 ГБ;
# одновременно удаляются неиспользуемые компоненты: arm64 QEMU, бэкенд Vulkan, лишние языковые пакеты, утилиты самотестирования, ресурсы VR)
npm run runtime

# 2. Сборка инсталлятора EXE (цель electron-builder nsis, установка в профиль текущего пользователя)
npm run build:exe
# Результат: dist/release/ApkStart-<версия>-Setup.exe
```

Структура размера дистрибутива: Electron ~180 МБ, облегченный эмулятор ~480 МБ, системный образ с xz-сжатием ~1.1 ГБ. Итоговый установщик занимает ~1.32 ГБ (что примерно на 490 МБ компактнее сжатия gzip). Это физический предел оптимизации для `system.img` (полноценная ОС Android с защитой verity, из которой нельзя произвольно вырезать службы Google Play).

При первом запуске образ xz распаковывается в `%APPDATA%\apkstart\system-images` (~20 секунд, выполняется однократно) и в дальнейшем используется напрямую. Данные AVD и установленных приложений хранятся в `%APPDATA%\apkstart\avd`, поэтому они сохраняются даже при распаковке портативной версии во временные каталоги.

## Архитектура среды выполнения: полная независимость от сторонних эмуляторов

ApkStart — полностью **самодостаточный** проект. Все компоненты среды выполнения скачиваются, проверяются и изолированно хранятся в `%APPDATA%\apkstart\runtime`.

Легковесная версия по умолчанию скачивает полный пакет среды из **релизов этого проекта на GitHub** (`ApkStart-runtime-*.zip`), а при его недоступности переключается на официальные серверы Google:

| Компонент | Источник | Размер | Назначение |
|---|---|---|---|
| adb (platform-tools) | Официальный репозиторий dl.google.com | ~8 МБ | Установка и запуск Android-приложений |
| Android Emulator | Официальный репозиторий dl.google.com (загрузка в 8 потоков) | ~440 МБ | Движок среды выполнения (эмуляция устройств и трансляция GPU) |
| Универсальный системный образ Android 14 (Google Play x86_64) | Официальный репозиторий dl.google.com | Исходный ~3.1 ГБ (в xz ~1.1 ГБ) | Единый базовый слой: запуск приложений x86, ARM-библиотек и служб Google Play без дополнительной настройки |
| Драйвер AEHD (опционально) | Официальный репозиторий dl.google.com | ~0.2 МБ | Аппаратное ускорение (альтернатива HypervisorPlatform/WHPX в Windows) |

При первом запуске мастер в разделе «Среда выполнения» выполняет быструю настройку (**в один клик**):
1. Автоматическая загрузка adb, эмулятора и системного образа (скорость с официальных серверов 10+ МБ/с);
2. После развертывания происходит **автоматический запуск**; в дальнейшем приложения запускаются по клику на ярлык полностью прозрачно для пользователя.

**Совместимость с оборудованием (полная автоматизация)**

- При отсутствии аппаратной виртуализации происходит автоматический откат на программную эмуляцию; при сбоях запуска по очереди тестируются до 4 комбинаций параметров («бэкенд рендеринга → механизм ускорения → память / холодный запуск»).
- Параметр `-gpu` подбирается автоматически по версии движка (`software` для версий 37.x, `swiftshader_indirect` для более старых версий).
- Объём RAM и количество ядер рассчитываются исходя из характеристик ПК (2–4 ГБ RAM / 2–4 ядра), размер раздела данных оптимизирован с 16 ГБ до 4 ГБ; порт ADB выбирается динамически из свободных, пути с пробелами и кириллицей преобразуются в короткие пути формата DOS 8.3, блокировочные файлы AVD очищаются автоматически.
- Ошибки транслируются на понятный язык с конкретными подсказками по устранению; в настройках доступен экспорт диагностического отчёта.
- Загрузка больших файлов выполняется в **8 потоков с докачкой**; при отсутствии поддержки Range происходит откат на однопоточную загрузку.
- **Полная изоляция от других эмуляторов**: ApkStart не сканирует, не перехватывает и не использует сторонние эмуляторы (MuMu, LDPlayer, BlueStacks, WSA). Их установка, обновления и сетевые порты никак не влияют на работу ApkStart.
- **Проверка системы и автоконфигурация**: при первом запуске анализируются поддержка аппаратной виртуализации (VT-x/SVM), платформа гипервизора Windows, видеокарта и видеопамять, объем ОЗУ и версия Windows. Поддерживаемые параметры (память, ядра, профиль рендеринга) применяются автоматически; для параметров, требующих прав администратора, выводятся кнопки действий, а для настроек BIOS — инструкции. Подробнее: [docs/preflight.md](docs/preflight.md).
- **Патчи совместимости (профили оборудования)**: для нестандартных конфигураций (старые видеокарты с низкими версиями GLES, отсутствие аппаратного ускорения, проблемные видеодрайверы) предусмотрены JSON-патчи. Они описывают условия срабатывания и параметры запуска. В настройках можно импортировать, включать и экспортировать такие профили. Патчи изменяют только разрешённые параметры запуска и не содержат исполняемого кода. Подробнее: [docs/drivers.md](docs/drivers.md).

**Контейнерная оптимизация ресурсов**

- **Базовый слой только для чтения**: каталог `system-images/` хранится в единственном экземпляре для всех приложений (нет дублирования образов AOSP и Google Play).
- **Тонкий слой изменений (qcow2)**: пользовательские данные хранятся в виде дифференциального слоя + именованного снимка Quickboot. После закрытия последнего окна приложения состояние памяти сохраняется в снимок, и следующий запуск происходит за секунды из снимка вместо холодного старта.
- **Фоновый подогрев (включен по умолчанию)**: среда Android инициализируется в фоне при старте ApkStart (окна скрыты), поэтому клик по ярлыку приложения сразу выполняет команду `am start`. Потребление памяти в режиме ожидания составляет ~1 ГБ (можно отключить в настройках).
- **Ускорение холодного запуска**: кэширование проверок поддержки ускорения и версий компонентов на диске, отказ от избыточных вызовов `wmic`, адаптивный интервал проверки готовности гостевой ОС (от 350 мс), объединение команд инициализации в единый пакет adb (экономит 5–10 секунд при старте).
- **Генерация раздела `/data` на лету**: стандартный файл `userdata.img` в образах Google представляет собой пустую заглушку размером 1 МБ. Реальное форматирование обычно выполняет Android Studio; при прямом запуске `emulator.exe` этот шаг пропускался, из-за чего раздел `/data` не монтировался и система уходила в бесконечный цикл восстановления (recovery). В ApkStart при первом запуске генерируется валидный образ ext4 с размером блока 4 КБ, поддержкой шифрования `ENCRYPT` и атрибутов SELinux `ext_attr`, после чего расширяется через `qemu-img` + `resize2fs` до нужного объёма. Холодный старт занимает ~23 сек., восстановление из снимка — ~10 сек.
- **Проверка целостности снимков**: повреждённые или пустые файлы снимков (например, аварийно оборванный `snapshot.pb` размером несколько байт) автоматически распознаются и удаляются. Поддерживаются форматы именования `ram.bin` (новый эмулятор) и `ram.img` (старый эмулятор).
- **Подавление консольных окон**: консольные окна QEMU запускаются через `conhost.exe` с отдельным PID, а сетевой демон `netsimd` пытается открыть собственное окно. ApkStart подавляет появление чёрных окон на уровне перехвата создания окон, фильтрации по классам и заголовкам (emulator / qemu / netsim) с циклом проверки каждые 120 мс в первые 90 секунд старта.
- **Отображение только интерфейса приложения**: главное окно эмулятора (`Android Emulator - apkstart5554`) никогда не выводится на рабочий стол само по себе — оно либо скрыто, либо встроено в окно приложения через вызов `SetParent`. При закрытии окна эмулятор сначала аккуратно открепляется от окна-контейнера и прячется, и лишь затем разрушается родительское окно. Оконный прокси удерживает фоновый контроль до 3 минут, предотвращая случайное появление служебных окон.
- **Загрузка по требованию**: универсальный образ скачивается только при необходимости; раздельные пакеты `.apks` / `.xapk` устанавливаются через `install-multiple`.
- **Очистка и обслуживание**: сборка исключает архитектуры QEMU кроме x86_64 (экономия ~400 МБ); в настройках доступна очистка старых образов, устаревших снимков, файлов блокировок и остаточных AVD.

## Тестирование

```powershell
npm test                                   # Модульные тесты Node.js + тесты движка (без интернета)
npm run test:boot                          # Тест реальной загрузки: проверка параметров QEMU и выключения на Alpine 61 МБ
npm run selftest                           # Комплексная самодиагностика: проверка цепочки установка → запуск → скриншот → общая папка
electron test/electron-integration.js      # Интеграционный тест генерации ICO и ярлыков
electron . --smoke test\shot.png           # Запуск приложения и создание проверочного снимка экрана
```

Команда `npm run selftest` предназначена для проверки среды после установки: она последовательно проверяет подключение adb, версию Android, поддержку оконного режима freeform, двустороннюю синхронизацию общей папки, а при указании флага `--apk приложение.apk` выполняет полную цепочку: установка → запуск в отдельном окне → подтверждение фокуса → скриншот.

## Инженерные компромиссы (честно и открыто)

- **Это не написанный с нуля собственный гипервизор**: создание ядра Android, слоя трансляции GPU и среды ART требует многолетней работы крупных команд. Проект опирается на проверенный стек AOSP/QEMU/adb, сосредотачиваясь на бесшовной интеграции с Windows — ровно по такой же схеме построены Google Play Games на ПК и Tencent App Market.
- **Общая папка синхронизируется, а не монтируется напрямую**: без root-прав в среде Android невозможно прозрачно смонтировать файловую систему NTFS из Windows. Быстрая двусторонняя синхронизация даёт аналогичный результат без нарушения стабильности системы.
- **Приложения исключительно под ARM и приложения ByteDance**: включение режима совместимости с ARM в настройках переключает систему на образ **Android 14 (API 34) Google Play** с обновлённым транслятором `ndk_translation`, что позволяет запускать приложения, собранные только под архитектуру ARM. **Практический тест: приложение «Хунго» (Hongguo Short Drama, `com.phoenix.read`, только arm64-v8a) успешно устанавливается, открывает ленту рекомендаций и воспроизводит видео** — в старых образах API 30 из-за нестандартного обработчика сигналов возникало аварийное завершение (`DoBadTrampoline` SIGABRT), которое в Android 14 полностью устранено. Некоторые приложения со сложной защитой от эмуляции (проверка реальных датчиков или GSM-модуля) могут работать с ограничениями; при ошибке запуска ApkStart выводит подробное пояснение.

### Что делать при сообщении «Аппаратное ускорение не включено»

Для аппаратного ускорения эмулятора Android в Windows есть два пути:

| Технология | Что это такое | Требуются ли права администратора | Нужна ли перезагрузка |
|---|---|---|---|
| **WHPX** | Встроенный компонент Windows «Платформа низкоуровневой оболочки Windows» | Да (при включении компонента) | Да |
| **AEHD** | Официальный драйвер ядра от Google | Да (при установке драйвера) | Нет |

- **Установочная / Портативная версия**: откройте «Настройки → Проверка окружения» и нажмите **«Исправить»** рядом с пунктом «Аппаратное ускорение не включено». Появится запрос UAC, после чего система включит WHPX. Если включить компонент невозможно (не поддерживается системой либо отклонён запрос прав), программа автоматически установит драйвер AEHD.
- **Версия из Microsoft Store (MSIX)**: приложения из Магазина **не могут самостоятельно повышать привилегии**. Нажатие кнопки «Исправить» откроет стандартное системное окно «Включение или отключение компонентов Windows». Установите флажок напротив пункта
  **«Платформа низкоуровневой оболочки Windows»** (HypervisorPlatform), нажмите «ОК» и **перезагрузите компьютер**.

  Также можно включить компонент через PowerShell от имени Администратора:

  ```powershell
  dism /online /enable-feature /featurename:HypervisorPlatform /all /norestart
  dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
  ```

> Важно: недостаточно включить только «Платформу виртуальной машины» (VirtualMachinePlatform) — она используется для WSL2. Для эмулятора Android необходима именно **«Платформа низкоуровневой оболочки Windows» (HypervisorPlatform)**. Если включить только первую, команда `emulator -accel-check` покажет, что ускорение недоступно.
>
> Программа может работать и без аппаратного ускорения (в режиме программной эмуляции), но запуск может занимать несколько минут — предупреждение информирует именно об этом, это не критическая ошибка.

### Что делать, если иконка на рабочем столе отображается некорректно или показывает логотип ApkStart

Каждый ярлык приложения должен отображать **собственную оригинальную иконку** (при установке она извлекается из APK и сохраняется в `%APPDATA%\apkstart\icons\<пакет>.ico`). Если вместо неё отображается зелёная кнопка ApkStart или белый значок:

1. Откройте **«Настройки → Системная интеграция → Восстановить ярлыки»** (все ярлыки на рабочем столе и в меню «Пуск» будут пересозданы с правильными иконками и идентификаторами панели задач);
2. Если это не помогло, удалите ярлык, в главном окне ApkStart нажмите правой кнопкой мыши по приложению → «Создать ярлык на рабочем столе» (или переустановите приложение).

> Причина: в ранних версиях параметр `IconLocation` для ярлыков `.lnk` ошибочно указывал на иконку самого ApkStart; кроме того, при перемещении портативной папки абсолютные пути внутри ярлыков перестают совпадать. Восстановление ярлыков решает эту проблему.
>
> Каждый ярлык имеет собственный AppUserModelID, поэтому при **закреплении на панели задач** приложение сохраняет свою оригинальную иконку и не превращается в значок ApkStart.

### Почему команда `adb devices` не видит запущенное устройство

Служба adb в ApkStart работает на **выделенном порту 5044** и полностью изолирована от стандартного системного порта adb (5037). Это исключает конфликты с Android Studio, scrcpy и другими эмуляторами.

Для подключения через консоль укажите порт:

```powershell
$env:ANDROID_ADB_SERVER_PORT = 5044
adb devices              # покажет emulator-5554
```

⚠️ **Не выполняйте** ручное подключение `adb connect` к порту `5555`: на системных образах с Google Play появится системный запрос «Разрешить отладку по USB?», который перекроет окно приложения и заблокирует управление.
